# Due Passi — приложение для команды ресторана

Telegram Mini App для изучения меню и обучения сотрудников. Рабочий адрес: https://duepassi-staffbot.ru. Приложение открывается кнопкой меню Telegram-бота ресторана; сотрудники входят с кодом доступа, администрация — со своим кодом.

## Что умеет приложение

- Меню с разделами, поиском, фото, составами, вложенными компонентами и аллергенами.
- Техкарты лимонадов, милкшейков и чая. Нормы лимонадов на 0,4 и 1 л хранятся отдельно.
- Вино: вкладки «Бокалы» и «Бутылки». В бокалах — красные, белые и игристые вина с характеристиками. Цены и объёмы не показываются. «Бутылки» пока пусты.
- Соусы: состав, аллергены и список блюд, где используется соус. Раздел вычисляется из составов блюд; покупные соусы исключены из учебного каталога.
- Учебные тесты по блюдам, сохранение результатов и история сотрудников.
- Книга учебных материалов.
- Админка: редактор меню, создание и переименование разделов, код сотрудников, управление доступом сотрудников, результаты тестов.

## Инструкция сотруднику

1. Откройте приложение через Telegram-бота и введите код, полученный у руководителя.
2. В «Меню» выберите раздел или воспользуйтесь поиском. Нажмите на позицию, чтобы открыть карточку. Составные ингредиенты можно открыть отдельно.
3. В техкартах напитков сверяйте количество и единицы измерения; отсутствие количества означает, что норма не внесена.
4. Кнопка «Добавить в тест» позволяет выбрать блюда для следующего теста. Во вкладке «Тест» запускается проверка до 15 вопросов.
5. Дождитесь подтверждения сохранения результата. Если сеть пропала, повторите сохранение на том же экране.

Составы и аллергены должны соответствовать актуальным техкартам кухни. Приложение не заменяет уточнение состава у повара при аллергии гостя.

## Инструкция администратору

### Разделы меню

Откройте **Админ → Разделы меню**. Введите название и, при необходимости, короткое описание, затем нажмите «Сохранить раздел». Новый раздел появится в общем меню и списке разделов редактора. Вернитесь в админку, выберите его и нажмите «+ Добавить».

Для переименования нажмите существующий раздел в списке. Его позиции сохранятся: связь хранится по постоянному идентификатору, а не названию. Названия разделов не должны повторяться. Новые разделы добавляются в конец меню. Удаление и изменение порядка разделов через интерфейс пока не предусмотрены.

Новый раздел использует обычные карточки блюд: название, описание, состав, вложенные компоненты, аллергены, вес и подсказка. Специализированные режимы вина и техкарт напитков привязаны к исходным разделам; создание раздела с названием «Коктейли» само по себе не включает редактор техкарт.

### Позиции меню

В админке выберите раздел. Нажмите «+ Добавить» либо существующую позицию для редактирования. Основной состав и аллергены перечисляются через запятую. Вложенные составы вводятся по одному на строку, например:

```text
соус песто: базилик, масло оливковое, пармезан, орех кедровый
```

В лимонадах, милкшейках и чае используется редактор ингредиентов с количеством, единицей измерения и примечанием. Неизвестные нормы оставляйте пустыми. Сохранённые правки хранятся в рабочей базе и сохраняются при обновлении приложения.

Фотографии пока загружает технический специалист: нужно подготовить WebP, добавить файлы в `public/dishes` и связать путь с полем `dishes.photo` в базе через проверенное обновление. Загрузки фотографий и удаления позиций в интерфейсе пока нет.

Вино использует отдельное оформление. Характеристики хранятся в `components` под ключами «Подача», «Тип», «Стиль», «Происхождение», «Крепость», «Год урожая». Для изменения этих данных и наполнения вкладки «Бутылки» пока нужен технический специалист; обычный редактор блюд не является полноценным редактором винной карты.

### Доступ и результаты

- **Код сотрудников**: задайте новый четырёхзначный код. Он не должен совпадать с административным. Смена кода не завершает ранее открытые сеансы.
- **Сотрудники**: «Исключить» отключает доступ и удаляет сеансы сотрудника; «Вернуть» позволяет снова войти. Администраторов здесь отключить нельзя.
- **Результаты тестов**: история попыток по сотрудникам. Это учебный инструмент, не защищённая экзаменационная система: правильность ответов подсчитывается на клиенте.
- Код администратора меняется на сервере в `ADMIN_ACCESS_CODE`, затем перезапускается служба. Не храните действующие коды и токен бота в GitHub или этом README.

## Передача ресторану

Передайте ответственному сотруднику:

1. Владение ботом через BotFather и доступ к управлению его кнопкой меню.
2. Доступ к проекту Selectel и SSH сервера; настройте ключ нового владельца и проверьте подключение до удаления старых доступов.
3. Доступ к домену, DNS и продлению домена; проверьте оплату сервера.
4. Доступ к репозиторию GitHub и право публиковать обновления.
5. Коды входа и серверные секреты отдельным защищённым способом.
6. Актуальную резервную копию базы и инструкцию восстановления ниже.

После передачи проверьте вход сотрудника и администратора, создание раздела, сохранение позиции и результата теста. Смена административного кода сама по себе не отзывает существующие административные сеансы; их отзыв должен выполнять технический специалист отдельно при необходимости.

## Технологии

- **TypeScript** — язык приложения; **React 19** — интерфейс.
- **Next.js 16 (App Router)** — страницы, сборка и серверный API `/api/app`.
- **CSS** — адаптивное оформление без отдельной библиотеки компонентов.
- **Telegram Web App SDK** — интеграция с Telegram; сервер проверяет подпись данных Telegram через Web Crypto API.
- **Node.js 22** — серверная среда исполнения (не ниже 22.13).
- **SQLite + better-sqlite3** — меню, разделы, сотрудники, сеансы, результаты и настройки; WAL-режим.
- **WebP** — оптимизированные фото, отдельные версии 480 и 960 px.
- **Selectel, Linux, systemd, Caddy** — хостинг, управление процессом, HTTPS и проксирование.
- **Git / GitHub, npm, ESLint, TypeScript, node:test** — версии кода, зависимости, проверки и тесты.
- **Drizzle, Vite/Vinext, Wrangler/Cloudflare** — зависимости и конфигурации прежней инфраструктуры. В текущем запуске на Selectel не используются; не запускайте старые команды Cloudflare для обновления рабочего сервиса.

## Структура проекта

- `app/page.tsx` — экраны меню, обучения и администрирования.
- `app/globals.css` — оформление.
- `app/api/app/route.ts` — API, авторизация, начальные данные и одноразовые обновления базы.
- `lib/db.ts` — рабочее подключение SQLite.
- `lib/recipes.ts`, `app/components/recipe.tsx` — техкарты напитков.
- `lib/sauces.ts` — учебный каталог соусов.
- `data/sections.json`, `data/drinks.json`, `data/wines.json` — начальные данные. Правка этих файлов не заменяет редактирование уже заполненной рабочей базы.
- `data/allergen-review-2026-09-15.json` — данные одноразового обновления аллергенов; используются кодом, не удалять.
- `public/` — фотографии и учебные материалы.
- `ops/` — настройки службы, Caddy и обслуживание резервных копий.
- `tests/` — автоматические проверки.

## Локальный запуск

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Заполните `.env.local`: `SITE_URL`, `DATABASE_PATH`, `TELEGRAM_BOT_TOKEN`, `EMPLOYEE_ACCESS_CODE`, `ADMIN_ACCESS_CODE`. Для разработки используйте отдельного бота и отдельную базу; никогда не подключайте локальный эксперимент к рабочей базе. Для полноценного входа через Telegram локальный сервер должен быть доступен через HTTPS и настроен в тестовом боте.

Проверки перед публикацией:

```sh
npm run lint
npm test
DATABASE_PATH=/tmp/duepassi-build-check.sqlite npm run build
```

Служба production запускается командой `npm run start`. При смене версии Node.js пересоберите `better-sqlite3` (`npm rebuild better-sqlite3`). Не копируйте `node_modules` с macOS на Linux.

## Рабочий сервер и обновление

- Адрес сервера: `135.106.184.78`, сайт: `https://duepassi-staffbot.ru`.
- Текущий код: `/opt/duepassi/app` — ссылка на выпуск в `/opt/duepassi/releases/`.
- Служба: `duepassi.service`, процесс работает от пользователя `duepassi` на `127.0.0.1:3000`.
- Node.js: `/opt/node22/bin`.
- Окружение: `/etc/duepassi/app.env`.
- Рабочая база: `/var/lib/duepassi/duepassi.sqlite`.
- Резервные копии: `/var/backups/duepassi/`.

Проверка состояния:

```sh
systemctl status duepassi --no-pager
journalctl -u duepassi -n 100 --no-pager
curl -f https://duepassi-staffbot.ru/api/app
```

Без авторизации API возвращает пустое меню — это ожидаемо. Не публикуйте содержимое файла окружения или журналы с персональными данными.

Обновление выполняет технический специалист:

1. Проверить изменения и сохранить коммит в GitHub.
2. Создать отдельный каталог выпуска; установить зависимости под Linux через `npm ci`. Собрать с временной базой `DATABASE_PATH`, отдельно от работающего выпуска.
3. Сделать согласованную резервную копию рабочей SQLite. Сохранить прежний путь выпуска.
4. Остановить службу, переключить `/opt/duepassi/app` на новый выпуск, запустить службу. Не менять серверные секреты и путь рабочей базы.
5. Проверить ответ API, вход в Telegram, меню и сохранение изменений.
6. При ошибке вернуть ссылку на прежний выпуск и перезапустить службу. Возврат старой базы удалит более новые действия сотрудников, поэтому выполняется отдельно и только при необходимости.

Не собирайте приложение поверх каталога `.next` работающего выпуска.

## Резервные копии и восстановление

GitHub содержит код и статические файлы, но **не рабочие данные и не секреты**. Используйте SQLite backup API или команду `.backup`, а не копирование открытого файла SQLite в WAL-режиме.

Пример ручной копии на сервере:

```sh
sudo install -d -m 700 /var/backups/duepassi
sudo sqlite3 /var/lib/duepassi/duepassi.sqlite ".backup '/var/backups/duepassi/manual-backup.sqlite'"
sudo chmod 600 /var/backups/duepassi/manual-backup.sqlite
```

Выбирайте новое имя для каждой важной копии. Скрипт `ops/duepassi-backup` и таймер в `ops/` предназначены для регулярных копий; проверьте их фактическую установку через `systemctl status duepassi-backup.timer`. Скрипт удаляет копии старше 14 дней. Храните важные копии также вне сервера.

Для восстановления остановите `duepassi`, сохраните текущую базу и её WAL/SHM-файлы отдельно, замените базу проверенной резервной копией, уберите из рабочего пути старые WAL/SHM-файлы, восстановите владельца `duepassi:duepassi` и запустите службу. Проверьте `PRAGMA quick_check`, вход и данные. Восстановление откатывает изменения после даты копии.
