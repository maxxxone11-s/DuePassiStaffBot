# Due Passi · Команда ресторана

Telegram Mini App для обучения сотрудников ресторана. Приложение работает локально и подготовлено к серверному запуску.

## Запуск

1. Установите Node.js версии 22.13 или новее. Если используете `nvm`, выполните `nvm install 22`, затем `nvm use 22`.
2. В папке проекта выполните `npm install`.
3. Запустите приложение командой `npm run dev`.
4. Откройте `http://localhost:3000`.

Локальный код сотрудника: `1111`. На сервере код задаётся в окружении или админ-панели.

Локальный код администратора: `8475`. На сервере используется `ADMIN_ACCESS_CODE`.

## Подключение к Telegram

1. Откройте в Telegram бота **@BotFather**.
2. Создайте бота командой `/newbot` и сохраните выданный токен.
3. Добавьте токен на сервер как секрет `TELEGRAM_BOT_TOKEN`.
4. В BotFather выполните `/setmenubutton`, выберите созданного бота и укажите публичный HTTPS-адрес приложения.
5. Открывайте приложение только кнопкой меню бота: тогда Telegram передаст подтверждённые имя, username, фотографию и уникальный ID сотрудника.

Не публикуйте токен бота в коде, переписке сотрудников или Git.

## Сервер

Рабочее приложение размещено на сервере Selectel. Текущий стек: Next.js, Node.js и SQLite (`better-sqlite3`). Файлы Sites / Cloudflare остались от предыдущего варианта размещения и не описывают текущий рабочий запуск.

- `ops/duepassi.service` запускает приложение из `/opt/duepassi/app` на `127.0.0.1:3000`.
- Окружение службы читается из `/etc/duepassi/app.env`.
- `DATABASE_PATH` должен указывать на `/var/lib/duepassi/duepassi.sqlite`, вне папки кода.
- Caddy обслуживает HTTPS и передаёт запросы приложению.
- Начальное меню добавляется только в пустую базу. Существующие блюда, переименования и результаты при обновлении сохраняются. Уже появившиеся дубликаты автоматически не удаляются.

### Проверка локальных изменений

```sh
npm run lint
npm test
npm run build
```

После смены версии Node.js выполните `npm rebuild better-sqlite3`. Не переносите `node_modules` с Mac на Linux: устанавливайте зависимости на сервере под его версией Node.js (`npm ci`).

### Обновление рабочего сервера

1. Сохраните текущий коммит и резервную копию базы. GitHub хранит код, но не рабочую SQLite и не секреты окружения. Скрипт `ops/duepassi-backup` создаёт согласованную копию SQLite в `/var/backups/duepassi`; перед использованием проверьте, что его путь к базе совпадает с `DATABASE_PATH` службы. Копии старше 14 дней этот скрипт удаляет, поэтому важную копию перед обновлением сохраните отдельно.
2. Соберите и проверьте новую версию в отдельной папке выпуска. Не запускайте сборку поверх `.next` работающего приложения. Для проверки используйте временную базу, а не рабочую.
3. Переключите службу на проверенный выпуск, сохранив прежние секреты, путь к базе и конфигурацию Caddy. Перезапустите службу и проверьте вход, меню и сохранение теста в Telegram.
4. При проблемах верните предыдущий выпуск кода. Добавленные столбцы совместимы с предыдущей версией. Восстановление старой базы откатит и новые результаты сотрудников, поэтому не подменяйте её без необходимости.

Точные команды обновления зависят от фактической конфигурации сервера. Файлы в `ops` — ориентир, настройки работающей службы необходимо сверить перед развёртыванием.

### Telegram и тестирование

Приложение раскрывается при открытии и отключает вертикальные свайпы сворачивания в Telegram 7.7+. Свайп за верхнюю шапку Telegram всё равно может свернуть приложение. В старых клиентах остаётся обычное раскрытие.

Результат теста подтверждается только после ответа сервера. При ошибке можно повторить сохранение на том же экране; повторная отправка нового клиента не создаёт дубликат. Уже открытые старые клиенты сохраняют совместимость.

Сервер проверяет диапазон баллов (0…число вопросов, от 1 до 15 вопросов). Подсчёт правильных ответов пока остаётся в клиенте: это обучающий тест, а не защищённая экзаменационная система.

Перед рабочим использованием сверьте составы и аллергены с актуальными технологическими картами ресторана.

## Техкарты напитков

В основном меню есть разделы «Лимонад», «Милкшейки» и «Чай» — по 5 позиций с предоставленных фотографий IMG_9086, IMG_9087 и IMG_9088. В лимонадах нормы на 0,4 л и 1 л хранятся отдельно; переключатель не масштабирует рецепт. Сиропы, молоко и фреш указаны в мл; фрукты, ягоды, пюре, мороженое и остальные весовые ингредиенты — в г. Штучные количества сохранены как на фото. Если количества нет, ячейка остаётся пустой. Выход напитка, вода, лёд и нормы украшений не добавляются от себя.

Первичные данные находятся в `data/drinks.json`. Обновление добавляет напитки в существующую SQLite один раз, с отметкой `drinks_seed_v1`; блюда кухни, сотрудники и результаты сохраняются. Последующие изменения названий и норм из админ-панели не перезаписываются. Редактор содержит отдельные поля для ингредиента, количества с единицей и примечания для каждого объёма. Напитки добавлены как техкарты в меню; случайный тест по блюдам кухни сохраняет прежний набор категорий.
